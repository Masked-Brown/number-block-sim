# CONTEXT.md - local rules for `_infrastructure/`

You are in the rulebook folder. Four files, four write disciplines. The ways a fresh agent
goes wrong here, in order of likelihood:

1. **Never edit inside the SNAPSHOT markers in INFRASTRUCTURE.md.** The block is generated by
   the sweep; a hand-edit is detected (stamp hash) and overwritten. Edit the hand-written
   index above the markers only if your work order says so.
2. **Never add a rule to NORMS.md.** Rules enter only by promotion through the human gate
   (D28). If you have learned something rule-shaped, record it in your touchdown (a `gap:`
   note or a proposal); the loop routes it.
3. **CHANGELOG.md is append-only.** Add your entry at the end. Never edit or reorder existing
   entries.
4. **DESIGN.md is the only file here you may freely improve**, and nothing depends on it. It is
   non-authoritative and long by nature (the onboarding answer). If your work order edits a canon
   or operations file, update DESIGN.md in the same act and add a CHANGELOG.md entry [D34].

If you cannot find something, write a `gap:` note inline in your touchdown as it happens, and
carry on.
